# JIA Media Desk

`program.html` is a Program Team workspace preview linked from both existing pages. It has a calendar with fictional items and a Sunday program whose blocks can be added, edited, removed, and reordered with a drag handle or arrow buttons. Each block names a person or team, a media cue, and the checks it needs. Changes stay in that device's browser storage and can be reset. They do not sync between devices, update Drive, or notify anyone. Do not enter real member birthdays or private contact details in this public preview. The Program Flow and run sheet remain the official sources.

`index.html` is the published, sample-only demo. It has no login or shared storage. All changes reset on reload.

`live.html` is the shared-readiness pilot. It connects to the team-owned `jia-media-desk` Firebase project on the no-cost Spark plan. The JIA Media account has `role:"shared"` membership. The current service is `2026-09-27` and is open. The shared account can record station checks and readiness for that date. A test Camera response was saved, observed in a second tab, then reset to all checks false and Waiting; its timestamp remains visible. The source run sheet, procedures, assets, and incident log remain in Drive.

On September 27, a phone sign-in through the GitHub Pages URL failed in Safari with Firebase's "missing initial state" error. The live page now uses `https://jia-media-desk.firebaseapp.com/live.html`, the same origin as Firebase's sign-in helper, and Google redirect sign-in. The live page also has a three-item **Before pre-worship** checklist from the [Program Flow](https://drive.google.com/file/d/1SWlV6LEeAKeF2pVnzaVrCRnKNvO9rhD2/view), checked September 27, 2026. It saves under `services/{serviceId}/setup/pre-service` separately from station go-signals. Each check saves online; the completion button requires all three checks. The shared sign-in records an account and time, not a verified person. Publish the updated `firestore.rules` before publishing the page update so the new listener can read the checklist.

The current local page is designed for one assigned operator on one phone. It shows church setup, all five station checklists, and the Floor Director handoff in one scroll, with 48px buttons and no remote fonts. It uses the JIA Alabang green palette and an official logo copy. This is a workflow choice, not a technical lock: anyone with the shared JIA Media sign-in can still change these responses. The phone needs internet access to save; offline or unverified state disables changes and directs the operator to confirm directly.

## Connect the pilot

1. The team owner controls station access and Sunday rollover. Keep the existing Floor Director's direct go-signal as the fallback.
2. Cloud Firestore is in Singapore (`asia-southeast1`). Publish `firestore.rules` as the complete rule set **before** adding a member or opening a service. The rule set must be republished after any change to this file.
3. The Firebase web app config in `live-config.js` is public by design. Access comes from Authentication and Firestore rules. Never put passwords, private keys, or service-account credentials in this repository.
4. The current shared-account pilot has one `members/{uid}` document with `{active:true, role:"shared"}`. This account can update any station after a service is opened, and the website cannot attribute a response to a person. Do not distribute the account password through this repository. For future individual accounts, `role:"lead"` plus one `station` or `role:"director"` remains supported.
5. Create `services/YYYY-MM-DD` with `{date:"YYYY-MM-DD", open:true}`. Set `settings/current` to `{serviceId:"YYYY-MM-DD"}`. The site starts with all five stations waiting. For the next service, create its document and change only the current pointer. Close the old service with `open:false`.
6. Build the Firebase Hosting folder with `sh build-firebase-hosting.sh`, then deploy Hosting for project `jia-media-desk` using Firebase CLI. Do not deploy Firestore rules in this step. Publish the GitHub Pages redirect after the Firebase link is working.
7. Before relying on it, test the assigned phone and a second device: complete and reopen the pre-service checklist, and verify it updates on the other device; then check all three items for one station, mark it Ready, and verify that the handoff summary updates on the other device. Verify an unapproved account cannot read or write and offline or lost access shows **Unverified**. Keep direct verbal/radio confirmation for the first real service.

The pilot records only three check booleans, a ready response, the authenticated UID, and a server timestamp for each station. With a shared account, the UID identifies the account, not the person. It does not copy the run sheet or incident log. `firestore.rules` denies all client changes to membership, the selected service, and service metadata; those are controlled by the team owner in Firebase Console. Google Drive permissions still govern the linked files.
